# ArcadeBloom

ArcadeBloom is a curated directory for independent browser games, game-jam projects, unusual experiments and AI games. Each listing explains what a game is, credits its creator and links to the official place to play.

**Live site:** [arcadebloom.com](https://arcadebloom.com)

## How the directory works

Most catalogue entries are outbound links to their creators. The [play library](https://arcadebloom.com/play/) contains explicit owner-authorized exceptions: Circle Club, Pulse Lock, Echo Vault and the pinned CC0 Web build of Anarch. Hosting is restricted by [`scripts/lib/hosted-games.js`](scripts/lib/hosted-games.js) and ADR-0013 through ADR-0015; it does not extend to other third-party games.

Every published entry records its source, official play URL and available licence information. AI labels are based on creator disclosures and distinguish AI used during gameplay from AI-assisted creation. Unknown details are left unknown rather than inferred.

The catalogue covers Puzzle, Action, Arcade, Strategy, Racing & Sports, and Simulation. Entries come from verifiable sources including js13kGames, open-source repositories and independent creator sites.

## Development

Use Node.js and npm. The current [CI workflow](.github/workflows/ci.yml) runs Node.js 20. Run commands from the repository root; `npm ci` installs the versions in the committed lockfile.

```bash
npm ci
npm run serve
```

Open `http://localhost:8080` for the Eleventy development server. Before running browser tests for the first time, install Chromium with `npx playwright install chromium` (Linux CI uses `--with-deps`).

### Commands

| Command | Purpose |
| --- | --- |
| `npm run serve` | Compile CSS and start the Eleventy development server. |
| `npm run build:css` | Recompile Tailwind after style changes. |
| `npm run validate` | Check catalogue schema; report advisory warnings. |
| `npm run validate:strict` | Also block structural warnings, including duplicate URLs and inconsistent identities. |
| `npm run validate:collections` | Check collection content and directory membership. |
| `npm run build` | Strict validation, clean output, CSS, catalogue slug data, screenshots and Eleventy rendering. |
| `npm test` | Rebuild through `pretest`, then run the Playwright suite. |
| `npm run test:games` | Run challenge-game tests against an existing fresh build. |

The usual checks before committing are:

```bash
npm run validate
npm run validate:collections
npm test
```

To preview an existing build, run `npx http-server dist -p 4173`.

Playwright checks include console errors, outbound link attributes, content without JavaScript, SEO metadata and hosted-game behavior. HTML reports are saved under `test-results/html-report/YYYY-MM-DD/`.

## Project structure

```text
src/
├── _data/          # catalogue, tags and site configuration
├── _includes/      # shared layouts and components
├── static/         # browser assets; Circle Club under play/circle-club/
├── styles/         # Tailwind source and custom design tokens
└── *.njk           # Eleventy page templates
games/              # only named hosting exceptions are active; see below
scripts/            # catalogue import, validation and build utilities
functions/          # Cloudflare Pages Functions
tests/              # Playwright and data-policy tests
docs/               # architecture and operational documentation
dist/               # generated production output (gitignored)
.eleventy.js        # templates, filters, collections and asset copying
```

The production site is generated by Eleventy and deployed from `dist/` to Cloudflare Pages. Tailwind CSS is compiled locally; the site does not load the Tailwind CDN.

Active sources under `games/` are `pulse-lock/`, `echo-vault/`, `_shared/` and `anarch/`. Eleventy copies approved runtime files into `dist/play/`. Other legacy game directories and root files such as `index.html`, `game-detail.html`, `all-games.html`, `js/` and `games-data.js` are retired; do not edit them or use them as the catalogue.

## Catalogue changes

The authoritative schema is documented at the top of [`src/_data/games.js`](src/_data/games.js). Before changing catalogue data, read [`CONTEXT.md`](CONTEXT.md) and the current decisions in [`docs/adr/`](docs/adr/).

### Add or update a game

1. Verify the creator, official play URL and available licence information. Use `NOASSERTION` for an unknown licence and `unknown` for an unknown release date.
2. Edit [`src/_data/games.js`](src/_data/games.js), filling the schema fields. New entries need a unique `sourceKey` (for example, `github:owner/repo`) and a monotonic ID. Preserve existing slugs.
3. Select a category from [`site.js`](src/_data/site.js) and tags from [`tags.js`](src/_data/tags.js). Include gameplay tags and consistent `licenceStatus` metadata; do not introduce free-text tags.
4. Write an original, source-grounded tagline, introduction, getting-started instructions and feature list. Use only screenshots you have permission to publish. Never invent ratings, play counts or provenance.
5. For disclosed AI use, include `ai.types` (`ai-gameplay` and/or `ai-assisted`), `ai.note`, `ai.sourceUrl` and `ai.checkedDate`. Omit AI metadata when use is unknown. A gameplay review or review-registry entry is not required.
6. Run the validation and test commands above. The build regenerates detail pages and eligible discovery pages automatically.

Import utilities live under `scripts/`: `fetch-js13k.js` / `build-catalogue.js`, `fetch-leereilly.js` / `merge-leereilly.js`, and `write-games-js.js`. Review generated catalogue changes for attribution and duplicates before committing.

### Listing and search indexing

[`scripts/lib/directory-policy.js`](scripts/lib/directory-policy.js) controls eligibility for robots, sitemap, RSS and Collections. An entry needs attribution, an official HTTP(S) play URL and meaningful non-placeholder copy: at least five words in the tagline, 30 in `about` and 10 in `howToPlay`.

- `directoryStatus: draft` or `unlisted` prevents indexing; an omitted status means listed, subject to the content checks.
- Categories need at least 20 games to appear in navigation; tags need eight games to generate a page.
- The AI landing page stays noindex until eight content-qualified AI games exist.
- Historical evidence files and review registries do not grant indexing eligibility.

See [ADR-0011](docs/adr/0011-indie-and-ai-game-directory.md) for the current directory policy. AI Dungeon scenarios require creator submission or explicit permission, a Published direct share URL, and an Everyone or Teen rating; Discover is not bulk-imported.

## Deployment

| Setting | Value |
| --- | --- |
| Platform | Cloudflare Pages |
| Production branch | `main` |
| Build command | `npm run build` |
| Output directory | `dist` |

PR CI runs strict catalogue validation, Collection validation, the production build and Playwright. Content pages are static HTML with clean URLs such as `/game/<slug>/`. Generated `dist/_redirects` provides 301 mappings; Pages Functions under `functions/` return 410 for retired legacy URLs. A plain local static server previews the generated pages but does not emulate Pages Functions.

## Contributing

Read [`AGENTS.md`](AGENTS.md), [`CONTEXT.md`](CONTEXT.md) and the applicable [architecture decisions](docs/adr/) before substantial changes. [`CONTRIBUTING.md`](CONTRIBUTING.md) contains additional contribution guidance; where its legacy review or hosting wording conflicts, follow the current ADRs described above.

Use four-space indentation in HTML/JavaScript, kebab-case slugs and file names, Title Case game titles and sentence case descriptions. Keep commit subjects short and imperative. PR descriptions should list affected pages and games, explicitly identify catalogue changes, and include before/after screenshots for UI changes. `npm run validate` and `npm test` must pass before committing.
